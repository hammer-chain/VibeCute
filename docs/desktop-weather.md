# 桌面雨与天气预览

偏好设置 → 桌面雨提供总开关。打开“跟随城市天气”后，搜索并选择城市；检测到当前有雨时显示雨效，当前无雨时待机。关闭跟随后为持续下雨的手动模式。大小、速度、风向、数量、雨声与音量均保存到当前应用偏好域。雨声默认关闭。

开发者模式 → 桌面天气预览提供小雨、中雨、大雨、下雪、雷雨；晴天和阴天没有预览入口或绘制效果。预览直接运行本地渲染器，不发起天气查询，不修改已保存的总开关与城市；声音遵循“天气音效（雨声与雷声）”开关与音量，下雪静音。停止预览或关闭开发者窗口后恢复真实天气控制。雨天预览也会触发可见蓝鱼的避雨动作。

“天气音效”沿用原雨声开关和音量，保留用户已有静音选择。下雨循环播放原有24秒本地雨声；雷雨叠加5.5秒本地雷声，闪电出现约0.55秒后播放一次，每12秒一个周期。多屏共用时钟和播放器，不按屏幕叠加雷声。切换为普通下雨立即停雷，切换下雪、关闭、锁屏和休眠停止全部天气声音。

雷声由 `scripts/generate_weather_audio.py` 使用标准库离线合成，固定随机种子，不含外部录音或下载素材。`thunder.wav` 为24kHz双声道16位PCM，528,044字节；播放时不合成、不联网。拖动滑块只调整现有播放器音量，不重新解码。开发者预览里的音效开关与普通偏好共用。

雨滴实际撞上蓝鱼头顶钢盆时，会在角色上层产生短促水花和淡白色撞击圈，叠加轻微金属滴答声。接触点随15个顶盆姿势、缩放和朝向改变；窗口先挡住雨时不会产生新水花/音效。到达遮雨区停敲击声，收盆或动作中断清空水花。原32张动作图没有重绘。

钢盆音效是同一脚本原创合成的0.24秒单声道PCM，11,564字节；共用天气音效开关，响度为主音量的32%，每次略微变速。最多两个复用声部，全局最多每秒8次，雨/雷/盆合计最多4个播放器。每角色最多64颗水滴，复用已有30Hz时钟；最多2个钢盆，每盆9个轮廓点，以包围盒先排除远处雨滴，不新增窗口查询。`scripts/register_basin_surfaces.py` 离线生成配准点，改动/校准素材后需重跑；进程内只读取一次JSON，不逐帧读图。

## 天气来源和边界

- Apple 的公开接口 [WeatherKit](https://developer.apple.com/weatherkit/) 需要开发者账号、WeatherKit capability 和签名；本项目当前不采用读取 Weather 私有数据库的方式。
- 使用 [Open-Meteo 当前天气接口](https://open-meteo.com/en/docs)，无需 API key。查询只发送用户选择城市的坐标；搜索时向其地理编码服务发送输入的城市名，不申请设备定位权限、不发送会话或屏幕数据。
- 地理编码由 [Open-Meteo / GeoNames](https://open-meteo.com/en/docs/geocoding-api) 提供，搜索最多五条，必须点击确定城市，避免同名地点混淆。
- 只读取 current 的 weather_code、rain、showers；不使用未来降雨概率、当天最严重天气或纯降雪量来触发雨效。雨量是前一时间段的累计量，天气为模型估计，不是本机或窗外传感器。
- 晴/多云/阴（码0—3）直接待机，即使累计雨量字段与其矛盾也不显示效果。雷雨码95、96、97、99保留为雷雨类型，自动触发雷电与音效；普通雨不会打雷。
- 数据时间不得超过 30 分钟或领先本机超过 5 分钟。网络错误、非法响应和过期数据暂停自动雨效，不把未知状态当作晴天，也不沿用历史雨效。
- 自动每 15 分钟请求一次，单个请求最长 25 秒；同时最多一个天气请求。手动检测至少间隔 60 秒。关闭、切换城市取消旧请求，已取消的迟到结果不能重新启用雨效。不保留天气历史。
- 免费接口限非商业用途，服务条款见 [Open-Meteo Terms](https://open-meteo.com/en/terms)。商业分发前需配置合适的付费服务或自托管端点；界面保留数据来源署名。

## 性能和验收

雨、雪、雷雨最高 30 FPS；晴与阴不创建效果窗口或帧计时器。每屏雨线最多 1600 条、水花最多 600 个，雪花最多 240 个。普通窗口边界最多每 100ms 查询一次，全屏覆盖窗口鼠标穿透且不获取焦点。关闭、锁屏、显示器休眠时销毁动画计时器、雨声/雷声播放器及覆盖窗口；解锁/唤醒按保存状态重建。

雨模拟约为 O(屏幕数 × 粒子数 × 可见普通窗口数)，绘制为 O(粒子数)。窗口列表跨屏共享，不在每个屏幕重复查询；窗口/粒子数有界，但窗口数会影响碰撞成本。几何计算不读取标题或屏幕像素。

运行 `bash scripts/desktop_rain_checks.sh` 检查同源几何、天气码、过期/错误处理、取消与防重复请求、真实 AppModel 的自动/手动/关闭、预览状态恢复与粒子上限。该命令包含原生 AppKit，需本机图形会话。输出位于 `output/desktop-rain/`。独立的 release 优化模拟计时和签名 App 的 CPU/RSS 观测单独记录，不能用 debug 局部计时代替整应用性能验收。

多显示器、全屏、Mission Control 与真实系统睡眠仍需设备验收。窗口是矩形近似；CGWindowList 数据是否完整取决于系统，不能承诺逐像素遮挡。

2026-10-18 本机签名开发版短测（同一桌面、空会话、关闭口型等功能，预热4秒后各采样12秒）：关闭雨效 CPU均值0.59%，开启标准雨效2.65%（单核100%口径）；RSS峰值41.44→58.69 MiB，footprint峰值18.21→284.61 MiB。雨效新增全屏透明渲染后，内存成本不能仅看RSS；WindowServer/GPU的独立开销尚未采样。约15.6秒观察到467帧、125次窗口查询；关闭场景0帧、0次窗口查询、0次天气请求。证据 `output/desktop-rain/app-performance-comparison.json`。这不代表多显示器或长期稳定性能已验收。

优化模拟基准：`bash scripts/desktop_rain_performance.sh`，2560×1440，当前5种效果各测0/40/160个窗沿及0/2个钢盆，预热150帧后统计300帧；预算16ms，保留粒子数量上限断言。初版7种效果的历史最慢组p95约3.35ms。它不含真实窗口采集、绘制及系统合成成本。


## 蓝鱼顶盆避雨

可见的蓝色大肥鱼（Harness 绑定或独立角色）随实际雨效触发：拿盆起身 → 顶盆跑 → 放盆坐下 → 完全收盆 → 恢复思考。已在前台窗口遮住雨的地方时保持原位。前台窗口按同一份系统窗口列表中最前的普通窗口确定，不激活、移动或调整其他应用窗口，不读取标题、内容或屏幕像素。

目标必须完整落在窗口内部，并留8点边距；起点低于窗口下沿时跑到下沿内侧，高于下沿则优先保持当前高度，就近寻找能完整容纳角色与盆的位置。窗口下方的延伸雨影不作为终点。只在当前显示器可用区域内移动。窗口移动、关闭、切换、风向、角色比例或屏幕尺寸变化时重新规划。

没有合适目标时，以当前避雨失败的位置为中心，最多左右各56逻辑点（随角色比例缩放）往返，碰到屏幕约束缩短范围；连移动空间也没有时原地跑。目标丢失后不会跑回远处的旧出发点。雨停播放收盆坐下；显示器休眠、锁屏或角色关闭立即释放动作。手动移动会立即中断，并至少等待3秒再重新尝试。开发者动作预览优先，唱歌和普通口型不能盖住拿盆画面；其他角色照常显示。

角色资源与帧序见 [rain-shelter-artwork.md](rain-shelter-artwork.md)。

### 避雨性能约束与检查

以下是依据当前桌面角色规模提出的工程预算：同屏最多两个独立蓝鱼组，32帧资源按需解码一次，像素存储固定40 MiB；首次解码预算250ms，常规一次协调更新预算2ms。不新增计时器、天气请求或窗口列表采集；复用现有动画时钟，移动最多30Hz，每个角色规划最多2Hz，每次对窗内合法区间作常数次夹紧。每帧复杂度O(蓝鱼组数)，规划O(蓝鱼组数)，不随桌面像素数或窗口总数增长。资源按进程共享且固定32帧，朝向只做绘制变换；规划随前台边界、风向、尺寸变化失效，关闭不保留运动计划。

`bash scripts/rain_shelter_checks.sh` 需要本机图形会话，覆盖同源雨影/风向、负屏幕坐标、全周期、窗口移动/消失、112点往返、左右朝向、拖动中断、雨停、锁屏暂停、睡眠通知/唤醒、其他角色隔离、自动干/湿天气、手动模式及雪/雷雨预览。性能检查包含50,000次固定规模纯规划，以及原生角色窗口更新。具体数据与原生绘制图片位于 `output/rain-shelter/`；它们不等同于完整桌面合成验收。

`swiftc -parse-as-library Tests/RainShelterWindowFixture.swift -o .build/rain-shelter-window-fixture` 后，运行 `python3 scripts/rain_shelter_smoke.py` 对最终签名开发版做整应用短测：同一个测试自建40点宽前台窗口、隔离偏好、空会话、无音频，雨关/雨开往返各预热4秒并采样12秒，同时验证真实位置往返且雨关0帧/0窗口查询。指标包含CPU、RSS和物理footprint；雨开的数据包含雨覆盖层与角色两者，不能将增量全部归因于角色。原始证据 `output/rain-shelter/signed-app-performance.json`。

仍未独立测量WindowServer/GPU，多显示器实机、长期运行和真实锁屏/系统睡眠仍需设备验收。当前矩形窗口近似与采集权限边界沿用雨效实现。
